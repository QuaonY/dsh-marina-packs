# 极简示例

这是一个示例整合包，展示如何创建和分享 DSH Marina 整合包。

> ⚠️ **注意**：这只是一个示例，不包含真实的插件。请勿在实际环境中使用。

## 📝 介绍

这个示例整合包演示了：
- 最基本的 pack.json 结构
- README 文档的编写方式
- 整合包的目录组织

适合作为创建新整合包的参考模板。

## 🎯 适合谁使用

- 想要创建自己整合包的开发者
- 需要了解整合包格式的用户
- 贡献者参考示例

## 🚀 使用方法

### 作为模板使用

1. 复制 `example-minimal` 目录
2. 重命名为你的整合包名称
3. 编辑 `pack.json`：
   - 修改 `name`、`description`、`author`
   - 替换插件列表为真实插件
   - 更新版本和标签
4. 编写详细的 `README.md`
5. 添加预览图（可选）

### pack.json 字段说明

```json
{
  "schema_version": 1,              // 固定为 1
  "name": "显示名称",                // 用户看到的名称
  "version": "1.0.0",               // 遵循语义化版本
  "author": "GitHub用户名",          // 你的用户名
  "description": "简短描述",         // 一句话说明用途
  "tags": [...],                    // 分类标签
  "requirements": {
    "min_runtime": "2.0.0",         // 最低运行时版本
    "recommended_runtime": "2.5.0"  // 推荐版本
  },
  "plugins": [                      // 插件列表
    {
      "name": "plugin-name",        // 插件包名
      "version": "^1.0.0",          // 版本范围
      "enabled": true,              // 是否启用
      "config": {                   // 非敏感配置
        "key": "value"
      }
    }
  ]
}
```

## 💡 提示

### 版本号规范

使用语义化版本（Semantic Versioning）：
- `1.0.0` - 首次发布
- `1.1.0` - 新增功能
- `1.0.1` - Bug 修复
- `2.0.0` - 破坏性更新

### 插件版本范围

- `1.0.0` - 精确版本
- `^1.0.0` - 兼容版本（推荐）
- `~1.0.0` - 小版本兼容
- `*` - 任意版本（不推荐）

### 标签选择

选择 1-5 个最相关的标签：
- 场景类：development, writing, research
- 技术类：ai, code, data
- 难度类：beginner, intermediate, advanced
- 特性类：minimal, lightweight, full-featured
